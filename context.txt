Product is TWO LOOPS, one token wallet. Do not add student-vs-company Groq
fights (API cost). Do not fold the Nowadays dining challenge into this game.

1) LARP BATTLE (people vs people)
   Confirmed expo guests only (~795). Each person is pre-scored ONCE (O(n)).
   A fight compares two flex_scores and stitches a templated compliment + roast.
   No Groq required for v1. Optional live roast later if a Groq key is pasted.

2) SLOTS (company quiz as the other loop)
   Company intel becomes quiz/content, not Groq opponents.
   Question bank already exists (was built for a Crossy Road prototype).
   Slots are the likely v1 instead of Crossy Road physics.
   Spin is a token sink (unlocks / rerolls / cosmetics). Not internships, not fake merch.

Not v1:
- Company matching via Groq
- Pairwise precompute (~315k) or vs-51-companies (~40k)
- Wiring extra expo APIs for flavor
- Crossy Road physics if slots ship first
- Any server write path: no database, no accounts, no /api routes yet (Phase 2+)

What changed from the mock, and why:
- "ENTER YOUR NAME" is now "FIND YOUR CARD": you search the 795 real guests
  instead of inventing a persona. Your real LinkedIn IS the fighter.
- Profile shows the four real bars (32/32/26/10) and they sum to flex_score.
  scripts/test_web_data.mjs asserts that for all 795.
- Face-off hides both scores. The tap is a PREDICTION; the result says whether
  you called it. The rubric still decides the winner, never the vote.
- Trivia is the real 133-question deck, shuffled, no repeats until exhausted.
  Never display question.kind — "trap" gives the trick away.
- Tokens are credited once per resolved fight in the store, not per button tap
  (the mock paid a token on each of three result buttons).

Scores cluster hard: 90 of 200 random pairs have IDENTICAL totals. Two
consequences, both handled:
- suggestedOpponents() samples the gap-sorted pool on a quadratic curve so the
  challenger list is close fights first WITHOUT being all dead heats.
- A 0-margin result shows a DEAD HEAT badge and says what broke the tie
  (lower larp_index, else name order). This is exactly what Phase 4's Groq
  photo-finish judge is meant to replace.

TESTS — run these before believing anything works
  npm run typecheck
  npm run lint          eslint flat config; `next lint` is deprecated
  npm run test:data     bars sum to flex, photos exist on disk, ranks agree,
                        search/matchmaking/battle invariants
  npm run test:parity   200 pairs, lib/battle.ts vs larp_engine.battle(), 0 diff
  npm run test:flow     drives real Chrome through the whole game; fails on any
                        console error, page error, or failed request.
                        --url <base>  --shots <dir>  --headful
  puppeteer-core uses the installed Chrome. Set CHROME_PATH if it moves.

lib/battle.ts notes:
- Python compares the tuple (flex_score, -larp_index, name) and uses >=, so an
  exact 3-way tie resolves to the first argument. Ported exactly.
- The Python "judge's note" branch needs larp_index >= 40. The ceiling is 38 and
  the observed max across 795 is 20, so it is dead code and no Mersenne Twister
  is emulated. If larp_index gains a term, test:parity fails and that comment in
  battle.ts is where to look.
- `verdict` stays byte-identical to Python (parity + recording). `headline` and
  `tiebreak` are extra presentation-only fields the UI uses.

================================================================================
SCORING GOTCHAS (do not regress)
================================================================================

- school_tier() uses the school field only. Passing the whole profile blob
  false-positives "mit" inside "MIT-licensed".
- FAANG work equals T0 school. A named company that is not FAANG is 16, not 32.
  Hugging Face / Cursor / YC booths are other-prestige 24, not Apple.
- Presence is a WIN bar. Do not tax followers on larp_index.
- Projects capped at 10 so a Davis shipper cannot outscore Stanford+Stripe
  just by posting more LinkedIn project writeups.
- Re-scoring changes cards.json. Re-run `npm run data` and `npm test` after any
  weight change, or the four bars will stop summing to the flex score on screen.
